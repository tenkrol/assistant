# Спека домена tools

Инструменты модели: единый контракт `{ definition, executeDetailed, execute }`, реестр в одном месте, сеть только через `src/integrations/`, у каждого инструмента есть тест.

## ADDED Requirements

### Requirement: У инструмента один контракт
Каждый инструмент ДОЛЖЕН отдавать `{ definition, executeDetailed, execute }`:
`definition` — JSON-схема для модели, `executeDetailed(args, context)` — объект с полем
`text` (и данными результата), `execute` — строку с тем же текстом.

#### Scenario: Ошибка инструмента
- GIVEN инструмент получил неверные аргументы
- WHEN вызывается `executeDetailed`
- THEN возвращается объект с понятным `text`
- AND исключение не вылетает наружу

### Requirement: Реестр собирает инструменты в одном месте
Список инструментов для модели ДОЛЖЕН собираться из реестра, а не вручную в ядре.

#### Scenario: Новый инструмент
- GIVEN разработчик добавил модуль инструмента
- WHEN он регистрирует его в реестре
- THEN модель видит новый инструмент без правок `bot.mjs`
- AND остальные инструменты работают как раньше

### Requirement: Инструменты не ходят в сеть напрямую
Инструмент ДОЛЖЕН получать данные через домены или `src/integrations/`, а не вызывать сеть сам.

#### Scenario: Инструмент с погодой
- GIVEN инструмент погоды
- WHEN он нуждается в данных
- THEN он вызывает подключение из `src/integrations/`
- AND вне `integrations/` сетевых вызовов не появляется

### Requirement: У инструмента есть свой тест
Тест инструмента ДОЛЖЕН проверять его схему и `executeDetailed` на успех и на ошибку.

#### Scenario: Проверка инструмента
- GIVEN новый инструмент
- WHEN запускаются тесты
- THEN есть тест на успешный результат и на понятный отказ
- AND тест не поднимает мессенджер

## ADDED Requirements

### Requirement: /export умеет PDF
Команда `/export pdf` ДОЛЖНА отдавать выгрузку документом PDF с теми же разделами и данными,
что текстовая выгрузка, включая корректную кириллицу.

#### Scenario: Выгрузка в PDF
- GIVEN у пользователя есть память, напоминания и история
- WHEN он отправляет `/export pdf`
- THEN приходит файл `.pdf`
- AND в нём те же разделы, что в текстовой выгрузке
- AND кириллица отображается корректно

#### Scenario: Без аргумента
- GIVEN пользователь отправляет `/export` без формата
- WHEN команда выполняется
- THEN формат остаётся прежним (текстовая выгрузка)
- AND поведение не меняется

### Requirement: Ошибка сборки объясняется
Если PDF собрать не удалось (нет шрифта, нет данных, превышен размер), пользователь ДОЛЖЕН
получить понятный текст, а не пустое сообщение или молчание.

#### Scenario: Нет шрифта
- GIVEN на сервере нет шрифта с кириллицей
- WHEN пользователь просит `/export pdf`
- THEN приходит текст с причиной
- AND бот продолжает работать

## ADDED Requirements

### Requirement: Имя сопоставляется мягко
Инструмент `sendto` ДОЛЖЕН находить человека по сокращённой или полной форме имени, если
такой кандидат единственный.

#### Scenario: Полное имя вместо сокращённого
- GIVEN в справочнике один человек с именем «Маша»
- WHEN просят «напиши Марии, что задержусь»
- THEN сообщение уходит Маше
- AND подпись «От Вячеслава: …» сохраняется

#### Scenario: Двое кандидатов
- GIVEN под запрос подходят два человека
- WHEN инструмент ищет адресата
- THEN он не угадывает, а перечисляет кандидатов
- AND просит уточнить

### Requirement: Неизвестное имя не ломает отправку
Если имя не найдено, инструмент ДОЛЖЕН вернуть понятный текст со списком известных людей.

#### Scenario: Неизвестный адресат
- GIVEN имени нет в справочнике
- WHEN вызывается `sendto`
- THEN приходит текст со списком известных
- AND ничего не отправляется
