# Спека домена agent-link

## ADDED Requirements

### Requirement: Контракт v2 и совместимость
Связь с агентом ДОЛЖНА поддерживать версионируемый контракт v2 (`/v1/*`) и прежний режим
`/bridge`. Режим выбирается настройкой `AGENT_CONTRACT`; старый агент и старый env
работают без изменений.

#### Scenario: Новый агент
- GIVEN `AGENT_CONTRACT=v2`
- WHEN задача передаётся агенту
- THEN используется `/v1/tasks` с `requestId` и маршрутом
- AND ответ приходит событиями v2

#### Scenario: Старый агент
- GIVEN `AGENT_CONTRACT=v1` или агент не умеет v2
- WHEN задача передаётся агенту
- THEN используется прежний `/bridge`
- AND поведение совпадает с прежним

### Requirement: Постановка задачи с ключом и маршрутом
Постановка ДОЛЖНА передавать постоянный `requestId`, маршрут исходного разговора,
вложения через `fileId` и (при наличии) отобранные ассистентом личные факты для задачи.
Повтор с тем же `requestId` не создаёт вторую задачу.

#### Scenario: Задача из чата
- GIVEN владелец просит сложную работу в чате бота
- WHEN задача уходит агенту
- THEN в запросе есть `requestId`, `route` и файлы (если были)
- AND `context.facts` содержит только факты для этой задачи

#### Scenario: Потерян ответ
- GIVEN ответ агента на постановку не получен
- WHEN бот повторяет запрос
- THEN агент возвращает прежний `taskId`
- AND второго выполнения нет

### Requirement: События с подтверждением
Результат и вопрос агента ДОЛЖНЫ приходить событиями с постоянным `eventId`
(`<taskId>:<type>:<version>`). Получатель ДОЛЖЕН распознавать уже обработанное событие и
подтверждать обработку; повтор не создаёт второе сообщение.

#### Scenario: Повтор события
- GIVEN событие результата уже доставлено
- WHEN агент присылает его повторно
- THEN бот отвечает `processed: true` и `duplicate: true`
- AND второго сообщения нет

#### Scenario: Ошибка доставки
- GIVEN событие не удалось доставить
- WHEN бот отвечает ошибкой
- THEN `eventId` не считается обработанным
- AND агент повторяет доставку с тем же идентификатором

### Requirement: Вопрос агента и ответ владельца
Вопрос агента ДОЛЖЕН доставляться в исходный разговор; ответ владельца обычным сообщением
ДОЛЖЕН продолжаться той же задачей через контракт, а не создавать новую.

#### Scenario: Уточнение
- GIVEN агент задал вопрос
- WHEN владелец отвечает сообщением
- THEN бот отправляет ответ в задачу
- AND ожидающий вопрос снимается
- AND следующее сообщение владельца снова идёт обычным путём

#### Scenario: Просроченный вопрос
- GIVEN ответа нет дольше `AGENT_ANSWER_TIMEOUT_MS`
- WHEN бот замечает просрочку
- THEN ожидающий вопрос снимается
- AND владелец получает понятное сообщение

### Requirement: Файлы входа и результата
Вложения владельца ДОЛЖНЫ передаваться агенту через `/v1/files`, а файлы результата —
приниматься ссылками `fileId` и доставляться в чат. Произвольные пути и base64 в JSON не
допускаются.

#### Scenario: Задача с документом
- GIVEN владелец приложил документ
- WHEN задача уходит агенту
- THEN файл загружен и в задаче указан `fileId`
- AND при возврате результата файл доставлен документом

#### Scenario: Файл истёк
- GIVEN агент прислал `fileId`, срок которого истёк
- WHEN бот пытается скачать файл
- THEN текст результата доставляется
- AND владелец видит пометку, что файл недоступен

### Requirement: Ревизия и отмена
ДОЛЖНЫ поддерживаться ревизия результата (`revisionOf`) и отмена задачи агента; отмена не
создаёт отдельного пользовательского сообщения.

#### Scenario: Доработка
- GIVEN у агента есть готовый результат
- WHEN владелец просит изменить раздел
- THEN создаётся задача-ревизия с `revisionOf`
- AND прежний результат не удаляется

#### Scenario: Отмена
- GIVEN задача или вопрос агента ждёт
- WHEN владелец отменяет
- THEN агент получает отмену
- AND сообщение об отмене не дублируется

### Requirement: Служебное предложение памяти
Событие `memory_proposal` НЕ ДОЛЖНО создавать сообщение пользователю. Ассистент как
владелец личных фактов применяет или отклоняет предложение через свой слой памяти.

#### Scenario: Предложение принято
- GIVEN агент предложил факт
- WHEN ассистент его принимает
- THEN факт попадает в память ассистента
- AND пользователю ничего не отправляется

### Requirement: Маршрут только владельцу
Маршрут ответа ДОЛЖЕН приниматься только для настроенного владельца и площадки; чужие
`chatId`/`botId` отклоняются. Секреты в полях контракта не передаются и не логируются.

#### Scenario: Чужой маршрут
- GIVEN в событии чужой `chatId`
- WHEN бот его обрабатывает
- THEN событие отклоняется, `ack` не отправляется
- AND в лог пишется причина без секретов

## ADDED Requirements

### Requirement: Активность агентов в боте
Бот ДОЛЖЕН показывать реестр и последние события активности через контракт v2;
при недоступном/старом агенте — понятное сообщение без падения.

#### Scenario: /agents
- GIVEN мост v2 настроен
- WHEN владелец вводит /agents
- THEN приходит список агентов с профилем и возможностями.

#### Scenario: /activity
- GIVEN есть события
- WHEN владелец вводит /activity
- THEN приходят последние события с taskId/этапом/токенами.

## ADDED Requirements

### Requirement: Заявка из бота
Бот ДОЛЖЕН создавать draft-заявку через агентский `/v1/requests` и показывать
requestId и ссылку на сравнение; ошибки — понятным сообщением.

#### Scenario: /request
- GIVEN агент доступен
- WHEN владелец вводит /request <текст>
- THEN создаётся заявка
- AND видны requestId и compare URL.

## ADDED Requirements

### Requirement: Авто-заявка
Обычное сообщение с явным запросом на изменение продукта ДОЛЖНО создавать draft-заявку
без команды `/request`; неоднозначные сообщения идут обычным путём.

#### Scenario: «Добавь в бота …»
- GIVEN владелец пишет «добавь в бота команду …»
- WHEN сообщение обработано
- THEN создаётся заявка и возвращается requestId.

## ADDED Requirements

### Requirement: Разделение поручений и заявок
Обычные операции с данными (напоминания, календарь, память, поручения) НЕ ДОЛЖНЫ
создавать заявку на разработку. Заявка создаётся только при определённом намерении
изменить поведение продукта; неоднозначность требует уточнения.

#### Scenario: Напоминание
- GIVEN «Добавь напоминание завтра в 10:00 позвонить маме»
- WHEN сообщение обработано
- THEN создаётся/планируется напоминание, createRequest не вызывается.

#### Scenario: Доработка
- GIVEN «Добавь в бота возможность повторять напоминание до подтверждения»
- WHEN сообщение обработано
- THEN создаётся заявка или задаётся уточняющий вопрос, но не конкретное напоминание.

## ADDED Requirements

### Requirement: Ручной review в боте
Бот ДОЛЖЕН по `/review` показывать 1–3 предложения с источником/пользой/стоимостью/
проверкой либо явно сообщать об отсутствии сигналов.

#### Scenario: Нет сигналов
- GIVEN агент вернул пустой список
- WHEN владелец вводит /review
- THEN бот сообщает, что подтверждённых сигналов нет.

### Requirement: Контракт v2 передаёт проверенный principal
Постановка задачи через v2 ДОЛЖНА передавать `principal.userId` и `scopeId` из
проверенного контекста пользователя, отдельно от маршрута доставки.

#### Scenario: Задача второго пользователя
- GIVEN второй разрешённый пользователь поручает задачу
- WHEN бот вызывает `/v1/tasks`
- THEN `route` указывает место доставки
- AND `principal.userId` указывает автора
- AND значение не выводится из текста задачи.
