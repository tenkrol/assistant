# Техническое решение

## Как устроено сейчас
`reminder-tool.mjs`, `profile-tool.mjs`, `event-tool.mjs`, `file-tool.mjs`, `sendto-tool.mjs`
и другие отдают похожие объекты, но по-разному; `sendto` и поиск по истории собираются
внутри `bot.mjs`; инструмент опроса живёт в `polls.mjs`. Список инструментов ядро собирает
вручную.

## Предлагаемое решение
`src/tools/<имя>.mjs` с единой фабрикой и `src/tools/index.mjs` — реестр, который получает
зависимости (хранилища, подключения, домены) и отдаёт `definitions` и `executeTool(name, args)`.
`bot.mjs` использует реестр. Определения инструментов и тексты переносятся дословно.

## Влияние
Риск: потерять инструмент при переносе. Поэтому после каждого инструмента полный прогон
тестов, а проверка полноты — сравнение числа `definitions` до и после. Откат — `deploy-safe`.

## Альтернативы
- Оставить как есть: новый инструмент каждый раз правит ядро.
- Схема-описание через генератор: отвергнуто, лишняя сложность без нужды.
