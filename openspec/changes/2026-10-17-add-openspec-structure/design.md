# Техническое решение

## Как устроено сейчас
Правила — в чате и `docs/HANDOFF.md`; секреты — только `.env` на серверах.

## Предлагаемое решение
- `openspec/project.md` — контекст, серверы, домены.
- `openspec/conventions.md` — язык, тесты, коммиты, DoD, секреты, запреты.
- `openspec/specs/<домен>/spec.md` — поведение «как есть сейчас».
- `openspec/changes/<дата>-<имя>/` — proposal, дельта-спека, design, tasks.
- `tg-agent/tools/spec-check.mjs` — валидация без CLI (замена `openspec validate`).
- `tg-agent/tools/secrets.mjs` — AES-256-GCM + scrypt, пароль вне репозитория.
- `secrets/keys.md` — таблица «ключ → за что отвечает → где взять новый», без значений.

## Влияние
Код бота не меняется. Риск только организационный: дисциплина «сначала спека».

## Альтернативы
- Официальный CLI OpenSpec: отвергнут — лишняя зависимость, структура и так простая.
- Секреты в приватном репозитории открытым текстом: отвергнуто — утечка необратима.
