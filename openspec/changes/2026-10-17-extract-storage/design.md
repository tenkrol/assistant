# Техническое решение

## Как устроено сейчас
Каждый store (`reminders`, `events`, `profiles`, `usage`, `history`, `contacts`, `polls`)
сам реализует чтение, атомарную запись и обработку ошибок. Логика похожа, но расходится в
деталях.

## Предлагаемое решение
Один модуль `src/storage/json-store.mjs` — фабрика хранилища:
`createStore({ file, version, defaults, migrate, logger })` с методами `load`, `flush`,
`replace`, `snapshot`. Внутри: временный файл + `fsync` + `rename`, блокировка через
эксклюзивное создание файла-замка, чтение версии схемы и прогон миграций, откладывание
битых файлов в `<файл>.broken-<дата>`, резервная копия перед миграцией.

## Влияние
Форматы файлов не меняются, кроме добавления поля `version`. Риск: забыть перевести какой-то
store — поэтому переводим по одному и после каждого прогоняем полный набор тестов. Откат —
обычный `deploy-safe`.

## Альтернативы
- Оставить как есть: отвергнуто, расхождения уже приводили к потере данных.
- SQLite: отвергнут, проект принципиально без зависимостей.
