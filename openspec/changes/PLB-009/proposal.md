# PLB-009 — контракт v2 с агентом: события, файлы и вопросы

## Зачем
Агент перешёл на контракт v2 (`tenkrol/agent`, PLA-14): `/v1/tasks` с маршрутом ответа,
`/v1/files`, события `result`/`question` с постоянным `eventId` и подтверждением обработки
(`ack`). Чат-бот пока работает по старой схеме: `POST /bridge` без `requestId` и маршрута,
результат приходит текстом в `/outbox`, без дедупликации, файлов и обратного вопроса.
Из-за этого не работают адресные уточнения, повторная доставка и файлы результата.

## Что меняется
- **agent-link**: новый домен правил контракта v2 — постановка задачи с `requestId` и
  `route`, одиночный ответ на вопрос, отмена, ревизия, файлы входа/выхода; прежний `/bridge`
  остаётся как совместимый режим.
- **integrations**: транспорт агента (`agent-bridge`) учится `/v1/*` и `/v1/files`;
  получатель `/outbox` принимает события v2, скачивает файлы результата, отвечает `ack`.
- **delivery**: результат и вопрос агента доставляются в исходный чат, файлы — документами
  и фото; `memory_proposal` не создаёт сообщение пользователю.
- **storage**: журнал обработанных `eventId` (дедупликация) и ожидающие вопросы агента по
  чату — переживают перезапуск.
- **config**: режим контракта, лимит файлов, срок хранения журнала событий.

## Чего не делаем
- Не меняем агент: PLA-14 на его стороне уже реализован и задеплоен.
- Не переносим личную память в агент: `memory_proposal` только принимается ассистентом как
  владельцем личных фактов.
- Не обещаем отсутствия дублей при сбое посреди отправки в Telegram: для событий защита —
  постоянный `eventId` и наш журнал; платформа транзакций не даёт.
- Не переписываем ядро `bot.mjs`: изменения — через домен `agent-link` и тонкие вызовы.

## Как проверяем
- Контрактные тесты: `requestId`, `route`, `attachments[].fileId`, `context.facts`;
  идемпотентность постановки/ответа/отмены; ошибки `400/401/404/409/413/503`.
- Тест событий: `eventId` запоминается, повтор возвращает `processed: true` и не создаёт
  второго сообщения; результат и вопрос доходят в исходный чат; `memory_proposal` — без
  сообщения пользователю.
- Тест файлов: загрузка входа и скачивание результата, лимит размера, `404/410`.
- Тест совместимости: старый агент (только `/bridge` и текстовый `/outbox`) работает как
  раньше; `AGENT_CONTRACT=v1` отключает новый режим.
- Живой сценарий с агентом: задача с файлом → уточнение в чате → ответ → результат и файл
  в том же разговоре; повтор события после «потерянного» `ack` не дублирует сообщение.
