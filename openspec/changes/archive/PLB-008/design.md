# Техническое решение

## Как устроено сейчас
`public/app.html` — одна страница с русскими строками в разметке и в скрипте; ошибки API
приходят текстом с сервера (`src/miniapp.mjs`).

## Предлагаемое решение
- `public/locales/ru.json` и `en.json` — плоские словари ключ-значение.
- В `app.html` — `data-i18n="ключ"` на элементы и функция `t(key)` для скриптов; язык хранится
  в `CloudStorage`, при отсутствии берётся `language_code` из `initData`.
- Серверные ошибки: `src/miniapp.mjs` отдаёт код (`unauthorized`, `not_found`, …), клиент
  переводит его; тексты-заглушки остаются для совместимости.
- Тест: наборы ключей `ru.json` и `en.json` совпадают, в `app.html` нет кириллицы вне скриптов.

## Влияние
Риск: пропущенная строка. Поэтому тест на кириллицу в разметке и сравнение ключей.
Откат — обычный `deploy-safe`.

## Альтернативы
- Переводить на сервере: лишний запрос и кеш; словари в клиенте проще.
- Библиотека i18n: отвергнута, тянет зависимость ради пары десятков строк.
