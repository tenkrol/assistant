# PLB-006 — правило именования папок изменений

## Зачем
Сегодня папка изменения называется датой и слагом, и по имени не видно ни порядка, ни
номера. Владелец просит единую маску `PLB-<номер>`, чтобы ссылаться на изменения коротко
(«это в PLB-003») и видеть порядок.

## Что меняется
Все папки изменений называются `PLB-<трёхзначный номер>`: `PLB-001`, `PLB-002`, … Номер
уникален и берётся по порядку создания. Название изменения живёт в `proposal.md`, а не в
имени папки. Архив переименован ретроспективно: 001 — каркас процесса, 002 — storage,
003 — domain, 004 — integrations, 005 — tools.

## Чего не делаем
Не меняем структуру `specs/` (домены остаются по именам доменов) и содержимое изменений.

## Как проверяем
`spec-check` принимает только `PLB-<номер>`; в конвенциях, README и `AGENTS.md` правило
записано; архив и активные изменения переименованы.
