# Дельта для домена core

## ADDED Requirements

### Requirement: Невалидный chatId не попадает в историю
Запись истории ДОЛЖНА принимать только конечный числовой `chatId`; иначе сообщение не
сохраняется, а факт пишется в журнал.

#### Scenario: Сообщение без chatId
- GIVEN у входящего сообщения нет корректного chatId
- WHEN история пытается его сохранить
- THEN запись не создаётся
- AND в журнале есть предупреждение с причиной
- AND в истории не появляется ключ `NaN`

### Requirement: Поллинг переживает сетевые обрывы
При ошибке `getUpdates` бот ДОЛЖЕН повторять с нарастающей паузой; после серии подряд идущих
обрывов — один раз сообщить владельцу, после восстановления — сообщить, что связь вернулась.

#### Scenario: Серия обрывов
- GIVEN три обрыва `getUpdates` подряд
- WHEN бот повторяет запросы
- THEN пауза между попытками растёт
- AND владельцу приходит одно уведомление о проблеме со связью

#### Scenario: Восстановление
- GIVEN связь восстановилась после серии обрывов
- WHEN бот успешно получил обновления
- THEN приходит одно сообщение «связь восстановлена»
- AND дальнейшие повторы не спамят

### Requirement: Управление проактивностью из чата
Команда `/proactive` ДОЛЖНА показывать состояние проактивности пользователя и позволять
включить/выключить её, изменить время обзора и тихие часы; настройки персональные.

#### Scenario: Статус
- GIVEN у пользователя есть профиль проактивности
- WHEN он отправляет `/proactive`
- THEN видит включено/выключено, время обзора, тихие часы, сколько отправлено сегодня
- AND его настройки не меняются

#### Scenario: Выключение
- GIVEN проактивность включена
- WHEN пользователь отправляет `/proactive выкл`
- THEN доставки этому человеку прекращаются
- AND у других получателей ничего не меняется

#### Scenario: Время обзора
- GIVEN пользователь отправляет `/proactive обзор 08:30`
- WHEN команда выполняется
- THEN время обзора сохранено и подтверждено
- AND следующий обзор учитывает его
