# PLB-027 — защита истории, устойчивость поллинга, управление проактивностью из чата

## Зачем
Три дефекта из разбора 22.10:
1. В истории появился чат `NaN` (14 сообщений) — `chatId` не проверялся перед записью, и
   невалидный ключ сохранялся. Данные уже перенесены, нужна защита, чтобы не повторилось.
2. Telegram-поллинг теряет обновления: 14+ предупреждений `getUpdates: fetch failed` за сутки,
   сообщения в эти окна не доходят (например «Слав ты тут?» осталось без ответа).
3. Проактивностью можно управлять только правкой файла и окружения — нужна команда `/proactive`.

## Что меняется
Домен `core`: валидация `chatId` при записи истории, backoff и уведомление при серии сетевых
обрывов поллинга, команда `/proactive` со статусом, включением и настройками для каждого
получателя.

## Чего не делаем
Не меняем механики проактивности (это PLB-020…026) и не трогаем мост агента.

## Как проверяем
История не принимает невалидный `chatId` (тест); при обрывах бот повторяет с паузой и после
серии пишет владельцу один раз; `/proactive` показывает состояние, включает/выключает и меняет
время обзора и тихие часы для конкретного человека.
