# Техническое решение

## Как устроено сейчас
Изоляция — по `chatId`/`userId` в каждом хранилище. Общих пространств нет.

## Предлагаемое решение
1. Хранилище пространств `scope.json`: `{ id, kind: 'personal'|'shared', title, owner_id,
   members[{user_id, role}], created_at }`; личное пространство создаётся при первом обращении.
2. В записях данных добавляется `scope_id` (по умолчанию — личное пространство владельца);
   миграция существующих файлов: `scope_id = personal(owner)`.
3. Проверка доступа — один модуль `src/core/access.mjs`: `canRead(userId, record)`,
   `canWrite(userId, record)`, `scopeOf(userId)`, `sharedScopes(userId)`. Роль `owner` — всё,
   `member` — чтение и запись в общем, `viewer` — только чтение.
4. Команды: `/project new <название>`, `/project invite <id>`, `/project list`.

## Влияние
Риск: пропущенная проверка доступа. Поэтому все точки чтения/записи идут через `access.mjs`,
а тест перебирает каждый store. Миграция с копией файлов. Откат — `deploy-safe`.

## Альтернативы
Отдельные боты/чаты на проект — лишняя инфраструктура.
