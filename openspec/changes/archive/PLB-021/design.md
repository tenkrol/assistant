# Техническое решение

## Как устроено сейчас
Бот читает PDF/DOCX/XLSX для ответа в диалоге, файлы на выход собирает `tools/file-tool.mjs`
(рендер в `src/pdf.mjs`). Хранилища документов нет.

## Предлагаемое решение
1. `src/documents.mjs` (доменный) + `documents.json`: `Document{id,scopeId,storageRef,checksum,mime,
   processingStatus}`, `DocumentVersion{id,documentId,createdAt,extractionVersion,indexVersion}`,
   `Chunk{versionId,locator,text,quality}`. Оригиналы — в `data/documents/<id>/`, в общем слое
   хранения, миграция с копией.
2. Извлечение: существующие парсеры (PDF-текст, DOCX, OCR через уже подключённый сервис, если он
   есть; если нет — статус «ожидает обработки», не выдавая заглушку за работу). Индекс — термины
   + метаданные, семантика через существующую модель на этапе поиска.
3. Поиск и ответ: ACL через `src/core/access.mjs` до кандидатов; citations с
   `documentVersionId`, `locator`, `snippet`; ссылка на скачивание выдаётся только после проверки
   доступа и живёт ограниченно.
4. Версии — по checksum и подтверждению пользователя; сравнение по извлечённым блокам.
5. Удаление — каскад: оригинал, версии, чанки, кеш; документ-инструкция не исполняется.
6. Тестовый набор: 20 синтетических документов, 15 вопросов (10 с ответом, 5 без).

## Влияние
Риск: утечка фрагментов чужой области или выдуманные цитаты. Поэтому ACL до выдачи, фрагмент
проверяемый, при отсутствии подтверждения — честный отказ. Откат — `deploy-safe` с флагом
`DOCUMENTS_ENABLED`.

## Альтернативы
Paperless-ngx — отдельная инфраструктура и миграция, не для MVP.
