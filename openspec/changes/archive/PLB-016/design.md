# Техническое решение

## Как устроено сейчас
Есть модульные тесты (857) и ручные проверки владельца. Продуктовых сценариев нет.

## Предлагаемое решение
- `docs/acceptance/scenarios.json` — каталог: `id`, `bp` (BP-01…), `title`, `steps[]`,
  `expect`, `evidence`, `status` (done | partial | todo), `checkedAt`.
- `tg-agent/tools/acceptance.mjs` — `--list` (сводка по статусам), `--check` (валидация полей),
  `--show <id>`. Ноль зависимостей, запускается из корня репозитория.
- `test/acceptance.test.mjs` — каталог парсится, обязательные поля на месте, покрыты все
  реализованные фичи, у каждого сценария есть шаги и доказательство.
- Живые прогоны добавляются по мере появления HTTP-проверок: сейчас статус честно
  `done` только там, где прогон фактически был.

## Влияние
Только документация и инструмент; рантайм бота не меняется. Откат — обычный коммит.

## Альтернативы
E2E на Playwright/Telegram-клиенте — тяжёлая зависимость, откладываем до BP-05.
