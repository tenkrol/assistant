# Техническое решение

## Как устроено сейчас
- systemd-юнит без явного `Restart=always` (проверить и исправить).
- `deploy-safe` переключает релиз и перезапускает сервис, но не проверяет, что бот действительно
  поднялся и отвечает.
- Напоминания: просроченное при старте снимается без доставки.
- Обзор: кандидаты собираются по чату получателя (личка), беседы не учитываются.
- Мост: `/v1/activity` (agent) не отдаёт userId/scopeId, бот нормализует и фильтрует.

## Предлагаемое решение
1. Юнит: `Restart=always`, `RestartSec=5`, `StartLimitIntervalSec=0`; отдельный
   `tg-agent-watch.timer` с проверкой `/api/reminders` (401 = жив) и `systemctl is-active`,
   алерт через `agent-notify` (не чаще раза в час).
2. `deploy-safe`: после перезапуска — окно 60 с проверки `systemctl is-active` + HTTP-кода;
   провал → откат + уведомление.
3. Догон: при старте просроченные в пределах 12 ч доставляются с префиксом «пропущено, было на …»,
   старше — снимаются со счётчиком; идемпотентно по id.
4. Обзор: кандидаты собираются по всем чатам пользователя (список из history/scopes), с ACL
   по областям; пункты из беседы попадают только её участникам.
5. Мост: в агенте добавить `userId`/`scopeId` в активность (из контекста задачи), бот уже
   нормализует их в `taskPrincipal`.

## Влияние
Риск: залить чат догонами или алертами. Поэтому окно 12 ч, единичная доставка, алерт не чаще
раза в час. Откат — `deploy-safe`.

## Альтернативы
Внешний мониторинг сервисом — лишняя инфраструктура для двух ботов.
