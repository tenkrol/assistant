# Техническое решение

## Как устроено сейчас
Порт платформы объявляет необязательный `sendDocument`; в адаптере Telegram он есть, в VK — нет,
поэтому ядро честно отвечает «платформа не умеет». Инструмент `file` уже умеет собирать
PDF/Excel/Word/CSV, а отправку делегирует платформе.

## Предлагаемое решение
В `src/integrations/platforms/vk.mjs` реализовать `sendDocument({ chatId, bytes, fileName, caption })`:
1. `docs.getMessagesUploadServer` с типом `doc` и `peer_id` получателя;
2. POST файла на выданный URL (multipart);
3. `docs.save` с полученным `file`;
4. `messages.send` с `attachment=doc<owner_id>_<id>` и подписью.
Ошибки загрузки/сохранения превращать в `VkError` с понятным текстом. Метод добавляет
`canSendFiles`/возможности для подсказок.

## Влияние
Новый сетевой путь в VK — единственный риск (лимиты размера и тип документа). Ошибки
обрабатываются и объясняются. Откат — `deploy-safe`.

## Альтернативы
- Отдавать ссылку вместо файла: требует публичного хостинга, хуже для приватности.
- Загружать через личные сообщения от пользователя: невозможно, бот работает как сообщество.
