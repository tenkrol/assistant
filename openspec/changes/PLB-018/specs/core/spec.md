# Дельта для домена core

## ADDED Requirements

Источник: пакет продуктовых спек 18.10, BP-03 «Проекты и общие пространства».

### Требования

1. Пользователь создаёт проект и явно добавляет туда поручения/материалы. Переключение активного проекта подтверждается краткой строкой; текущий проект виден в карточках.
2. Активный проект хранится на уровне пользователя и разговора/темы. Ответ на старое сообщение сохраняет область исходного объекта, даже если текущий проект изменился. При противоречии бот уточняет назначение.
3. Роли MVP: owner, editor, viewer. Editor изменяет материалы/задачи, viewer читает разрешённые материалы; управление участниками и удаление проекта доступны owner. По умолчанию проект личный.
4. Приглашение связывается с подтверждённой учётной записью и принимается получателем. Ссылка/пересылка карточки сама по себе не выдаёт доступ.
5. «Что по проекту?» возвращает актуальную сводку: незавершённые задачи, сроки, блокировки, последние решения и ссылки на источники. Устаревшая сводка пересчитывается либо помечается датой.
6. Архивирование прекращает новые фоновые инициативы проекта, сохраняя доступную историю. Удаление — отдельная операция по существующей политике.
7. Отзыв доступа действует для API, поиска, кеша, скачивания файлов и ожидающих доставки уведомлений. Уже отправленные сообщения нельзя считать отозванными: это ограничение явно описать.

### Данные и контракт

Project: id, owner_id, name, description, status, version. Membership: project_id, principal_id, role, status. Объекты ссылаются на scope_id/project_id. Не копировать личный объект в общую область автоматически: операция публикации требует явного выбора и проверки связанных вложений. Операции create/select/list/archive/invite/accept/revoke/summarize. Изменение состава участников инвалидирует кеши разрешений.

### Критерии приёмки

- Пользователь переключается между «Ремонт» и «Поездка» без смешения задач и памяти.
- Ответ на карточку из старого проекта изменяет именно её объект или запрашивает уточнение.
- Viewer не может изменить задачу через естественный язык, прямой API или callback.
- После отзыва доступа пользователь не получает очередное уведомление, результаты поиска или файл проекта.
- Добавление личного документа к общему поручению не открывает документ молча: нужна явная публикация либо отказ.
- Сводка не содержит удалённых/недоступных объектов, каждое фактическое решение имеет источник.
