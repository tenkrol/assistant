# Дельта для домена core

## ADDED Requirements

### Requirement: Приглашение требует принятия
Приглашение ДОЛЖНО создаваться в статусе `pending` с кодом, ролью и сроком действия; участником
оно становится только после принятия получателем. До принятия `canRead`/`canWrite` для
приглашённого не срабатывают.

#### Scenario: До принятия доступа нет
- GIVEN владелец пригласил пользователя B в проект
- WHEN B до принятия вызывает список проекта или ищет по нему
- THEN данных проекта он не видит
- AND в журнале нет обращений к проекту от B

#### Scenario: После принятия доступ есть
- GIVEN приглашение отправлено
- WHEN B принимает его своим подтверждённым аккаунтом
- THEN B становится участником с указанной ролью
- AND видит данные проекта согласно роли

#### Scenario: Пересылка не даёт доступ
- GIVEN код приглашения переслан третьему лицу
- WHEN А пытается принять его под своим аккаунтом
- THEN доступ не выдаётся, если приглашение адресовано B
- AND владелец видит попытку в журнале

### Requirement: Срок и отзыв приглашения
Приглашение ДОЛЖНО истекать по сроку; владелец может отозвать его. Просроченное и отозванное
не дают доступа.

#### Scenario: Просроченное приглашение
- GIVEN приглашение истекло
- WHEN получатель пытается принять его
- THEN приходит понятный отказ
- AND доступ не появляется

### Requirement: Идентичность не смешивается между платформами
Principal ДОЛЖЕН быть парой «платформа + подтверждённый идентификатор»; одинаковый числовой id
на разных платформах не даёт доступа к чужому проекту.

#### Scenario: Одинаковый id на разных платформах
- GIVEN в Telegram у пользователя id 7, в VK тоже 7 у другого человека
- WHEN приглашение выдано telegram:7
- THEN vk:7 доступа не получает
- AND principal в членстве хранится с платформой
