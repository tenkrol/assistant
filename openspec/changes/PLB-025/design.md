# Техническое решение

## Как устроено сейчас
- `tg-agent/public/app.html` — Telegram Mini App: один HTML-файл, тёмная/светлая тема из
  `Telegram.WebApp.themeParams`, вкладки «Напоминания / Календарь / Память / Статистика».
- Вход только по подписи `initData`; вне Telegram страница показывает заглушку
  «Откройте через Telegram». Сервер — `src/miniapp.mjs`, API: `/api/reminders`,
  `/api/events`, `/api/memory`, `/api/state`.
- Всё остальное (чат, голос, файлы, агент, настройки) живёт только в Telegram-чате.

## Предлагаемое решение
**Для макета (сейчас).** Статический прототип без сервера и зависимостей:
- `mockup/index.html` + `mockup/app.css` + `mockup/app.js` — интерактивный мобильный экран
  390×844 с пятью разделами, шторками создания и демо-данными;
- `mockup/board.html` — дизайн-борд: все экраны в рамках телефона, принципы, токены;
- `mockup/README.md` — как открыть, что нажимается, что заглушка, каким API соответствует.

**Для реализации (после одобрения).** Отдельная оболочка `public/mobile/` (или замена
`app.html`), которая:
1. В Telegram берёт `initData` как сейчас; в обычном браузере — Telegram Login Widget либо
   одноразовый код, который бот присылает в чат (короткий TTL, привязка к `user.id`).
2. Переиспользует существующие хуки и API мини-приложения; добавляет `GET /api/chat`
   (история), `POST /api/chat` (сообщение), `GET /api/agent/tasks`, `GET /api/files`,
   `GET|PATCH /api/settings`. Все записи — через те же хранилища, что и бот.
3. Отдаёт PWA-манифест и service worker для установки на домашний экран; оболочка
   кешируется, данные — всегда из сети (как сейчас: `cache-control: no-store`).
4. Сохраняет принцип «ноль npm-зависимостей»: только HTML/CSS/JS, иконки — инлайн-SVG,
   шрифты — системные.

**Навигация.** Пять разделов в нижней панели, подэкраны с «назад»: «Планы» → календарь,
«Ещё» → файлы/статистика/настройки. Активный раздел подсвечивается, состояние раздела
сохраняется при переключении.

**Чат.** Основной экран: история диалога, быстрые действия, вложения, голосовой ввод,
стриминг ответа, карточки-результаты (напоминание, файл, задача) прямо в переписке.

**Данные.** Напоминания, события, память и статистика читаются/пишутся через существующее
API; изменения сразу видны боту. Агент и файлы — новые тонкие эндпоинты над уже
существующими мостом и каталогом файлов.

## Влияние
Сейчас — нулевое: макет не подключён к серверу и не меняет `public/`. При реализации:
риск — доверие к `user.id` в браузерном входе (закрывается одноразовым кодом с TTL и
проверкой подписи на сервере), риск — дублирование логики с Telegram Mini App (решается
общим модулем API-клиента), откат — `deploy-safe`.

## Альтернативы
- **Доращивать существующий `app.html`** — меньше кода, но четыре вкладки уже тесны, а чат
  и настройки потребуют переписать разметку; выбран новый каркас с переносом вкладок.
- **Только Telegram Mini App** — не решает просьбу «сайт в браузере» и установку на домашний
  экран; оставляем как быстрый путь, но добавляем браузерный вход.
- **Нативное приложение** — дороже в поддержке, не нужно для двух человек.
