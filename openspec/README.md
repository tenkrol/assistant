# Как работаем (ритуал)

## Кто что делает
- **Владелец:** описывает задачу словами, смотрит спеку, одобряет или правит.
- **Агент:** пишет proposal, дельту-спеку, design и tasks; реализует, тестирует, деплоит,
  обновляет handoff и архивирует.
- Любая другая сессия или инструмент читает `AGENTS.md` в корне и продолжает по тем же правилам.

## Шаги
1. **Задача словами.** Например: «хочу, чтобы `/export` умел PDF».
2. **Спека.** Агент создаёт `changes/PLB-<номер>/`: `proposal.md` (зачем и что), `specs/<домен>/spec.md`
   (требования и сценарии GIVEN/WHEN/THEN), `design.md` (как), `tasks.md` (чек-лист).
   Владелец читает и одобряет.
3. **Реализация.** По `tasks.md`, с тестами. Если по ходу выяснилось, что спека неверна — правим
   спеку, а не молча код.
4. **Проверка.** Локальные тесты → `deploy-safe` → проверка живого поведения.
5. **Архив.** Дельта вливается в `openspec/specs/`, папка уезжает в `changes/archive/<дата>-<имя>/`,
   `docs/HANDOFF.md` обновляется, коммит и `git push origin <ветка>`.

## Имена папок
, , … — номер по порядку создания, тема в `proposal.md`.

## Статусы
- `changes/<папка>/` — в работе; `changes/archive/` — завершено.
- Если раздел спеки не описан — писать «не знаю», а не оставлять пустым.

## Проверка
```sh
bash tg-agent/tools/spec-check.sh     # структура changes и спек
node --test --test-force-exit          # тесты проекта
```
